## Monitoring

Prometheus loads `/etc/prometheus/rules/*.yml`. The athena disk rule group alerts when
`/` or `/mnt/hercules` crosses 80% used, escalates at 90% used, and warns when
`/mnt/hercules` is predicted to fill within seven days. The rule group reads
`athena_filesystem_*_bytes` metrics generated by
`prometheus_disk_space_textfile`, because the host's node exporter currently omits
`/mnt/hercules` from its built-in filesystem metrics.

Alertmanager on this host still has the Debian sample receiver configuration. The disk
rules are active once Prometheus reloads, but notification routing needs a real receiver
before alerts leave the box.

## Recurring Cleanup

`cron.jobs/cron.weekly/weekly_jobs` runs these guardrail cleanups:

- `docker builder prune -af`
- `docker image prune -af`
- `sudo apt clean`
- `uv cache prune`

Docker volumes are deliberately excluded from the scheduled cleanup. Cargo target
sweeping is wired as an optional step and logs a skip unless `cargo-sweep` is installed.
